# Dataset design — v1

The dataset must identify both the taught concept and why its label is credible. Shape contract: [sample.schema.json](contracts/sample.schema.json). JSONL contains one strict UTF-8 JSON object per line; maximum 128 KiB per sample, no blank lines. Model request limits still apply to nested input.

## Canonical sample

| Field | Required meaning |
|---|---|
| schema_version | `arbitrium.sample.v1` |
| sample_id | immutable opaque ID, unique within all dataset ancestry |
| family_id | connected family of scenario, paraphrases, template and contrast variants |
| task_id | matches input and manifest task |
| split | train, dev, calibration_fit, calibration_select, test |
| input | complete DecisionRequest; request_id equals sample_id |
| target | `{answerable: bool, label: string or null}`; label null iff unanswerable |
| concepts | nonempty unique curriculum concept IDs |
| difficulty | integer 1..5 |
| provenance_id | immutable audit record reference in manifest provenance index |
| review_status | `verified` only in frozen dataset |
| verification_kind | controlled_oracle, audited_paraphrase, human, execution_adjudicated |
| supersedes | previous sample ID or null; never overwrite prior record |

No calibration probability or teacher confidence is a target. Unanswerable examples are genuine supported-task ambiguity/missing evidence, not invalid API requests. Unsupported task/language/oversized input belongs in contract tests, not a learned abstention class. Decision labels for answerable records must exist in TaskSpec.

## Audit record (outside student data)

Every provenance ID resolves to immutable JSON with: schema_version `arbitrium.provenance.v1`; sample/scenario/template IDs; source kind and license/permission basis; source content hash; generator code/config digest; teacher and reviewer model IDs, weight hashes, quantization, server version/commit and chat-template hashes (null only for non-model authored records with explicit reason); prompt hashes; sampling settings; raw-response hashes; attempt IDs; proposed label/answerability; blind review label/answerability; review issues/disposition; verifier name/version/hash and expected outcome; final label source; human batch-audit reference where required; created_at UTC; supersedes lineage. Raw responses and rationales remain audit-only, never model input. A source outcome is only evidence under its documented conditions; successful retry does not prove retry was the best counterfactual choice.

Generation records may be rejected/quarantined/corrected; only verified records enter a frozen dataset. Correction creates a new sample with lineage and re-review. Unknown model version, missing audit or invalid license/permission basis blocks freeze. Retain rejected evidence for diagnosing label quality rather than silently deleting it.

## Grouping, leakage and split assignment

Create family groups before prose generation. Union scenario ancestry, paraphrase/minimal-pair ancestry and template family; related variants always stay together. Template here means an authored phrasing/logic skeleton; renaming an ID does not make a new family. Detect exact normalized input duplicates and normalized token 5-gram Jaccard >=0.80 candidate near-duplicates; reviewed semantic equivalents are unioned too. Do not merge every example merely because it shares the fixed question/policy: compute similarity on state plus varying policy content. After grouping, assign and freeze the groups. Newly discovered cross-split family links block release; do not silently move only the offending record.

Initial ratios by hash bucket: train 60%, dev 15%, calibration_fit 10%, calibration_select 5%, test 10%. Compute SHA-256 of UTF-8 `arbitrium-split-v1\n42\n` + family_id; unsigned first 8 bytes big-endian modulo 10000. Buckets [0,6000), [6000,7500), [7500,8500), [8500,9000), [9000,10000). Seed and family assignment are retained across versions. Ratios are targets; report actual counts without relocating convenient families. Generate additional new families if quotas are short. Split assignment is independent of model performance.

v1 experiment target: >=10,000 accepted records, with >=20% unanswerable in each split and approximately balanced labels among answerable records (each class within 20% of equal-share count). Require >=20 distinct template families total and >=3 in sealed test. Sealed test minimum is 1,000 records, >=100 per decision label and >=200 unanswerable. Calibration_fit minimum 1,000, >=100 per label and >=200 unanswerable; calibration_select minimum 500 with >=100 unanswerable. Dev minimum 1,000. Larger family counts are better evidence than many paraphrases of one family.

The sealed suite also includes independently authored controlled/human-adjudicated cases not generated by the current teacher run. It targets at least 20 held-out template families and requires at least 10; if that support cannot be assembled, the registered release experiment does not proceed. Report results by verification source; teacher-generated agreement alone is never evidence of independent generalization. Hold out both phrasing families and scenario combinations; balancing uses additional families, not post-test cherry-picking.

## Frozen layout and manifest

`datasets/frozen/<dataset-id>/` contains `manifest.json`, `task.json`, `train.jsonl`, `dev.jsonl`, `calibration_fit.jsonl`, `calibration_select.jsonl`, `test.jsonl`, `families.jsonl`, and `provenance-index.jsonl`. Audit contents may be in separately controlled storage addressed by digest. Teacher jobs cannot read calibration/test payloads; training reads only train/dev; calibration command reads only the two calibration splits. Host enforcement/access permissions complement these program boundaries.

Manifest required fields: schema_version `arbitrium.dataset.v1`, dataset_id, parent_dataset_id or null, task_id and task_sha256, curriculum_sha256, created_at UTC, generator_git_sha, split_algorithm/seed, normalization/dedup versions, files mapping (relative path→sha256/bytes/records), per-split counts (labels, answerability, concept, difficulty, family and verification kind), provenance index digest, audits, license summary, known limitations. `dataset_id` is an immutable logical label, not a content digest. The manifest does not hash itself; `dataset_digest` is defined externally as SHA-256 of the exact final manifest bytes and is the integrity identity used by runs/artifacts. File hashes refer to exact bytes, including LF endings. `created_at` is allocated once when freeze begins, journaled, and reused on resume so an interrupted freeze can reproduce the same manifest bytes. All files are immutable after freeze.

Freeze validates every record/schema, label mapping, referential integrity, audit eligibility, counts, no duplicate IDs/inputs, family separation, hashes and path safety. It writes atomically into a new directory and refuses to overwrite an existing dataset ID. C++ rechecks relevant hashes and contracts rather than trusting a Python `verified=true` flag.

## Next education cycles

Train changes create a new dataset version; frozen dev/calibration/test bytes and family assignments remain unchanged during one registered experiment. Feedback to teacher is aggregate dev slice statistics, not dev records or answers. New lessons must be new scenario/template families, disjoint from all holdouts. Dev is adaptive development evidence and is reported as such. If exact dev examples are deliberately reused, retire that dev suite and record contamination; never count it as independent validation again.

Tokenizer training uses train only. Calibration_fit never selects model weights; calibration_select only selects abstention thresholds. Test never selects architecture, hyperparameters, thresholds, prompt templates or curriculum. A contaminated sealed suite is retired and replaced under a new experiment ID before another claimed independent test.
